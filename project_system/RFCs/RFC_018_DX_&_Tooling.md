# RFC-018: Developer Experience (DX) & Tooling

**Status:** Planned for Beta 1 & Post-v1.0 **Components:** `waffle-commons/maker`, `waffle-commons/profiler` **Author:** Core Architect **Tags:** dx, scaffolding, profiling, testing

## 1. Summary

This RFC defines the tools aimed at improving the daily life of developers using the Waffle framework.

## 2. Motivation

A framework's success heavily depends on its Developer Experience. Waffle must provide scaffolding tools to reduce boilerplate and profiling tools to expose bottlenecks instantly.

## 3. Technical Specifications

### 3.1 Waffle Maker

An extension of the CLI console (`waffle-commons/console`) that provides scaffolding commands:

- `waffle make:controller`
    
- `waffle make:middleware`
    
- `waffle make:voter`
    
- `waffle make:dto`
    

### 3.2 API Profiler

Instead of a heavy HTML web profiler, Waffle will inject specialized HTTP headers (`X-Waffle-Time`, `X-Waffle-Memory`, `X-Waffle-Queries`) into the response when `app.debug = true`.

### 3.3 Testing Bridge

A specialized PHPUnit test case (`Waffle\Test\ApiTestCase`) that boots the Kernel in memory and allows simulating HTTP requests without booting a real web server, greatly speeding up the integration test suite.

## 4. Contributor Guidelines

- **Strict AST Generation:** Code generated by the Maker component must comply with Mago strict rules directly out-of-the-box (no trailing spaces, strict types declared).
    
- **Environment Isolation:** Profiler logic MUST be physically stripped or entirely bypassed in the `prod` environment to prevent information disclosure.
